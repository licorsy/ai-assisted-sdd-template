# Changelog

All notable changes to this template are documented here, starting from this file's own introduction. Prior history is recorded per-prompt in each `docs/prompts/NNN-<slug>.md`'s own Context/Task sections and changelog entries, and inside each `docs/manuals/*.md` file's own changelog — this file does not attempt to reconstruct that history retroactively. Entries describe each change as executed; file paths reflect the repository at that time and may since have moved (see `docs/prompts/PROMPT-INDEX.md` and each prompt's own file for current locations).

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

### Fixed

- Prompt `001`'s two deferred doc-consistency findings closed (`docs/prompts/016-close-restart-leftover-citations.md`), and the reason it deferred them turns out to be the whole point: they report identically to the `dead_citations` rule — a cited name resolving to no file — and need **opposite** treatments. `docs/reports/ARTIFACT-NECESSITY-AUDIT.md` justified two keep verdicts with claims about `CLAUDE.md` that are simply not true here: row 4 said the prompt-engineering guide is *"cited by `CLAUDE.md`'s AI-output rules"* (no such section exists) and row 14 said `token-economy.md` is pointed to by *"`CLAUDE.md`'s skill list"* (no such list exists). Both describe the archived private repository's `CLAUDE.md`, or conflate it with an operator's own global instructions file. The verdicts they support are correct — the guide and the token-economy file genuinely are cited, just by other files — so the fix re-points each to a citer verified by direct search (`README.md`, `agents/orchestrator.md`, `docs/prompts/basic-prompt-template.md`; and `README.md`'s Key documents section for the Graphify decision), rather than qualifying them as historical. **Qualifying a falsehood as a historical record preserves it and silences the check that would have caught it** — the distinction this batch exists to draw. `docs/reports/PROPOSAL-TRACKING.md`'s citations of `008-relatorio-melhorias-v6.md` are the opposite case: nothing about them is untrue, the report simply was never migrated and exists only in the archived private repository, so all three sites (that file's frontmatter `description` and source-report heading, plus `ARTIFACT-NECESSITY-AUDIT.md` row 16) now carry the established `archived private-repo sequence, not a citable path in this repository` qualifier — the same convention `003` applied by hand in about eleven places and `004` then taught the rule to respect, and which `PROPOSAL-TRACKING.md` already practised at one site of its own. The phrase is used verbatim because `.docgov.config.js`'s `exempt.self_qualifying` regex matches it literally, and it sits on the citing line because `lib/exempt.js` tests line by line — a note near the top of a file exempts nothing below it. Explicitly **not** done: the 567-item shadow backlog (`docs/manuals` 156, `docs/reports` 110, `docs/strategy` 101, `docs/prompts` 91, `agents` 55), the per-file `historical_paths` exemption that `dead_citations` supports but this repository does not set, and `004`'s open question of promoting the rule out of shadow — one decision spanning five directories, which a small cleanup should not settle as a side effect. `docs/reports/ARTIFACT-NECESSITY-AUDIT.md`'s own citations of `prompt-106`, `prompt-105` and `local-notes/012` are the same provenance class and were scoped out deliberately when this batch's boundary was drawn. One finding worth carrying into that later decision, learned by getting it wrong here: `lib/rules/dead-citations.js`'s `resolveCitedPath` resolves a bare filename **relative to the repository root**, not to the citing file — sibling-relative resolution is opt-in, only for paths explicitly prefixed `./`/`../` — so a bare filename cited from `docs/prompts/` is checked against the repository root and fails whenever no file of that name sits there, even when the file exists under `docs/reports/`. That is a convention the rule enforces — cite by repository-root path — not a defect in it, and it accounts for a meaningful share of the standing backlog: of the 139 distinct Markdown names cited repo-wide, **39 name a file that does exist somewhere but is cited from the wrong directory**. The first draft of prompt `016` violated that convention in its own text and was corrected before merge; the batch measures itself set-wise rather than by net count, because a prompt about unresolvable citations necessarily cites the same unresolvable names it discusses. Final delta: 567 → 564 shadow findings, but not four sites resolving one each: `PROPOSAL-TRACKING.md`'s frontmatter `description` edit produced no finding change, since `dead_citations`' filename pattern only matches a backtick-quoted path and that YAML field was never backtick-quoted; the third removal was incidental — qualifying `ARTIFACT-NECESSITY-AUDIT.md` row 16 exempted its whole line, which also silenced an unrelated, still-broken bare-filename citation of `docs/reports/PROPOSAL-TRACKING.md` (cited without its directory prefix) on the same line, rather than fixing it. Closed properly by `docs/prompts/017-fix-prompt-016-verification-findings.md`, which also corrects this entry's own resolution-mechanism description and manuals count above — both wrong in the original telling. **Archived 2026-08-06** once `017`'s own verification passed on pull request `#40`.

One real bug in the correction script itself was caught before any file was touched: its own "does this already resolve" check stripped a leading `/` before testing existence, which silently treated every leading-slash citation as already fine and skipped fixing it — the real `resolveCitedPath` never strips that slash, which is exactly why `dead_citations` flags those citations at all; caught by cross-checking the script's file-touched list against an independent count derived straight from the real backlog, not by re-reading the script. Verified as a **set**, not a net count: `docgov check` 564 → 301, exactly 263 findings removed (212 + 51), 0 new. `node --test .github/scripts/*.test.js`: 49/49. The template-target forward-reference category and the root-file scope gap are explicitly out of scope here — each needs a real design decision (a new exemption predicate that does not exist yet; a choice about creating three specific files), not a mechanical transform, and get their own prompts.
