# Changelog

All notable changes to this template are documented here, starting from this file's own introduction. Prior history is recorded per-prompt in each `docs/prompts/NNN-<slug>.md`'s own Context/Task sections and changelog entries, and inside each `docs/manuals/*.md` file's own changelog — this file does not attempt to reconstruct that history retroactively. Entries describe each change as executed; file paths reflect the repository at that time and may since have moved (see `docs/prompts/PROMPT-INDEX.md` and each prompt's own file for current locations).

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- Prepared the go-to-market separation without performing it (`docs/prompts/009-prepare-go-to-market-separation.md`). The founder's boundary — the template covers **building the product**, while **building a business from the product** is organization-level — puts one whole document on the far side: `docs/strategy/go-to-market.md`, whose seven phases are the business-building lifecycle. What **stays** is the half that is easy to get wrong: Phase 1's Activities 9, 10 and 12, `docs/business/market.md`, and the market-research acceptance criterion are *product discovery*, not commerce, and an earlier draft that moved them out was corrected. Verification then inverted the proposal's stated risk. It warned that moving the file would leave two owners for positioning and said to decide ownership first — but ownership is already decided in writing, and **the writing is inside the file slated for removal**: `go-to-market.md` is currently the only document in the repository stating that it *"references, and does not duplicate"* `roadmap.md` Activities 9-14. Deleting it is what would create the vacuum. So `roadmap.md` now carries that boundary statement itself, phrased to hold whether or not any commercial-roadmap document exists alongside it, and `ADR-0004` — which defines `docs/strategy/` as holding both files — is amended rather than left to contradict a future removal. Two further corrections recorded: the proposal's mechanical evidence (a grep it claimed returns nothing) actually returns one line, on "external contracts" in the API sense, so the conclusion survives but the evidence as stated does not; and its reference table, whose ten line numbers were all correct, missed three live references, one of them a `doc_type` enum row that `CHANGELOG.md` shows was already fixed once for this exact drift class. **The file itself is untouched and byte-identical** — the organization side must hold the content before a window opens in which it exists nowhere.
- Market-standard delivery vocabulary adopted, **re-scoped to what this repository actually contains** (`docs/prompts/008-market-standard-vocabulary.md`). The source proposal shipped with a costed migration plan and a stated blocker — a versioned marker convention, without which it declared itself "not adoptable". Verification dissolved the blocker: the `🎯 … CLOSED` marker it described as "the sole source of all phase/duration mining" appears in this repository exactly twice, both inside the proposal itself, and no parser for it exists anywhere (`duration_minutes` is a hand-written JSONL field; the only gate parser reads `#### Phase N - Generated artifacts` headings). The same held for `size-points`, which has no referent here at all, and for `cycle time`/`flow efficiency`, listed as "already correct, not touched" while being absent. Executing the plan as written would have meant *building* the things it proposed migrating. What was real is the ambiguity in `increment`, which named both the traversal and the thing the traversal delivers, in adjacent bullets of the same file: the process instance is now **release cycle**, the delivered capability keeps `Increment` — the Scrum term, already correct — and the two sites the text alone could not settle (Phase 6's goal, the security trigger) are ruled explicitly rather than guessed. The phase model now **declares itself Stage-Gate** (Cooper), which it always was; naming it takes on no dependency and changes no phase, following the precedent `agents/orchestrator.md` set when it named the reverse-the-conversation-direction practice. New `docs/manuals/glossary.md` carries all of it plus the four delivery surfaces — Roadmap, Board, Backlog, Reports — mapped onto this repository's **real** artifacts, correcting the proposal's mapping, which named a `specs/*/tasks.md` that does not exist here and "the observability artifacts", which is runtime instrumentation rather than a document set. The table lives in the glossary only: `README.md` explicitly refuses a second copy of the Document map, having drifted from one before. `Acceptance criteria / Done` deliberately **not** renamed — it is the phase-level heading, while `definition of done` already exists at task level, and collapsing them would lose a live distinction.
- New `docs/references/missing-data-vocabulary.md` (`docs/prompts/007-missing-data-vocabulary.md`): a shared shorthand for absent, degraded, or withheld data in anything a project renders for a human — `[x]` not available, `[z]` not applicable, `[c]` confidential, `[b]` break in series and the rest — plus the rule against the ambiguous `NA`, legend-above-the-table, and never joining a line across a gap. The *principle* was already settled here and stated in several places, each having invented its own token for the job — `agents/orchestrator.md`'s `not tracked (…)` and `none`, `generate-state.js`'s `—`, `gate-verification-template`'s `NOT MACHINE-CHECKABLE`, and both review agents' explicit non-findings; what was missing was the vocabulary letting them agree, so each now points at it rather than being rewritten, and the new reference owns the enumeration so no other file carries a count that goes stale. Adapted from the UK Government Analysis Function's published guidance, **verified at source rather than on the recommending note's word** — which showed the real symbol list is larger than the nine carried upstream, and confirmed the exact reasoning behind two of the rules (`NA` "is ambiguous"; joining across a gap "implies we know something about the data"). Its licence is recorded as `unverified` because neither page stated one, so the reference paraphrases and attributes rather than reproducing at length. `generate-state.js` fixed in the same change: it emitted `docs/STATE.md`'s own legend *below* the table, the exact placement the adopted guidance argues against, and the reason it argues against it — assistive technology walks a document in order. The convention deliberately ships without a mechanical check, and says why: it governs what a generated project renders, so there is nothing in this repository for a checker to scan.
- Absorbed the accepted half of an upstream sync batch carried up from `business-tech-agency`'s 2026-08-03 session (`docs/prompts/006-absorb-local-notes-011-accepted-items.md`, fourteen items). Verifying the batch's fifteen proposals against this repository first was what made it small: **twelve premises turned out to be false or incomplete here**, including both of the ones holding up the most expensive item — the `size-points` scheme it proposed renaming does not exist in this repository, and neither does the `🎯 … CLOSED` marker it called "the sole source of all phase/duration mining", nor any parser for it (`duration_minutes` is a hand-written JSONL field). Two roadmap self-contradictions fixed, each of which a downstream project had re-flagged and re-deferred for cycles: Phase 3's acceptance criterion claimed "SPEC becomes tasks" while Activity 12 of the same phase stopped short of tasks on purpose and every other document places task generation in Phase 4; and `test-report.md` sat under Phase 5's Generated artifacts with no statement of what `documentation-metadata-standard.md` already recorded, that it may be authored in either phase. Five conventions added that genuinely had no equivalent: verify a data source exists and holds real data *before* scoping a feature on it (new Activity 10a — lettered, not numbered, so the "Activities 9-14" citations do not break); a departure from an earlier same-cycle artifact carries its reason in the later artifact (the authoring half — detection was already covered three times over); acceptance criteria recorded per criterion in three states at the readiness gate, which `orchestrator.md` Step 3 never listed at all; "a figure with no attached decision is decoration"; and the task-artifact reconciliation at Phase 7 closure, adopted as written guidance only, with the reason the mechanical half is not adoptable here recorded rather than left implicit. `ADR-0003` gains a sixth principle — some facts are not retroactively derivable — as the declared counterweight to principle 4, whose derive-don't-duplicate instinct had no stated boundary; principle 4 itself now names the cumulative-fact ownership form directly. P9 widened from a taste prototype to a surface prototype covering information design, with all three copies of its trigger synced in the same edit, that pair having desynced once before. Deliberately *not* adopted: the source batch's "location decides legitimacy" rule (already covered in six or more places), and its "make specimens impossible, not plausible" rule as written — adopted scoped instead, so that `spec-prfaq-template.md`'s "invented but realistic" quote and the telemetry template's realistic sample lines stay correct rather than being contradicted on day one.
- Prompt `005` closed as **superseded**, not archived: its TASK items 2 and 3 never shipped and can no longer ship, because commit `9257c73` removed the Conventional Commits step they were meant to pin. What it had left behind was live — a `facts` block in `.docgov.config.js` carrying `shadow: false` and `entries: []`, a blocking rule checking nothing under thirteen lines describing a check that no longer existed. The block now pins the promotion chain instead: `CLAUDE.md`/`AGENTS.md` assert `develop → staging → main` as a permission matrix, `pr-checks.yml`'s `promotion-source` job enforces it as a base-ref mapping, and nothing linked the two — `check-adapter-sync.js` covers the adapter text, never the YAML. Verified by breaking it from both sides, per prompt 005's own surviving `[CRITICAL]` constraint. Prompt `004` archived: fully executed, its one open line (promoting `dead_citations` from shadow to blocking) an explicitly deferred decision rather than pending work.
- `.github/workflows/pr-checks.yml`'s `ci-docs` and `ci-security` jobs are now guarded by `if: github.repository_owner == 'licorsy'`. This repository is a GitHub template, so a project created from it inherited a silent dependency on reusable workflows the Licorsy organization controls and could change or delete; the guard makes that dependency explicit — outside `licorsy` both jobs skip, and the adopter chooses whether to repoint the `uses:` lines at their own copies or delete the `if:`. A job-level condition is the only option available: a reusable-workflow call supports no step-level `if:`, and `hashFiles()` is not a recognized function in job-level conditions (confirmed by a failed dispatch), so the capability-style guard `git-governance` uses cannot be copied here. `documentation-metadata-standard.md` Section 9 (v1.25 → v1.26) gains the matching caveat, since it previously promised adopters automation that a guarded job does not deliver.
